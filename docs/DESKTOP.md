# دليل تشغيل وبناء تطبيق سطح المكتب (Desktop Application Guide)
## منظومة المحاسب والمراجع القانوني المتكامل — MG Account

---

### 1. نظرة عامة (Overview)
تم تحويل المنظومة بنجاح إلى تطبيق سطح مكتب مستقل يعمل بواسطة **Electron** ومحزم بـ **electron-builder** مع استمرار العمل بكامل كفاءة النسخة السحابية والويب بدون أي كسر أو تعارض.

- **المحرك الداخلي:** خادم Express يعمل داخل نفس عملية التطبيق (In-Process) على المضيف المحلي `127.0.0.1` وعلى منفذ عشوائي حر يتم اختياره ديناميكياً لتفادي أي تعارض في المنافذ.
- **قفل النسخة الواحدة (Single Instance Lock):** يمنع تشغيل أكثر من نسخة واحدة من التطبيق في نفس الوقت، وعند محاولة فتح نسخة ثانية يتم نقل التركيز إلى النافذة المفتوحة مباشرة.
- **قاعدة البيانات:** SQLite مدمجة ومحلية عبر مكتبة `better-sqlite3` كمكتبة أصلية (Native C++) مع فك حزمتها في مجلد `app.asar.unpacked`.
- **التشغيل بدون إنترنت (100% Offline Capable):** كافة الخطوط وأيقونات الواجهة والأصول تعمل محلياً دون الحاجة لأي اتصال بالإنترنت.

### 2. مسارات حفظ البيانات الدائمة (Data Storage Persistence)
لضمان عدم فقدان البيانات أو تأثرها عند ترقية التطبيق أو تثبيت إصدارات جديدة، يتم حفظ كافة ملفات المنظومة داخل مسار بيانات المستخدم الرسمي لنظام التشغيل (`app.getPath('userData')`):

#### في نظام Windows:
```text
%APPDATA%\mg-account\data\
├── app.db               (قاعدة بيانات SQLite الكاملة)
├── app.db-wal           (ملف الذاكرة المؤقتة لكتابة المعاملات)
├── app.db-shm           (ملف الذاكرة المشتركة)
├── documents\           (مجلد المستندات المرفوعة وفواتير العملاء)
└── backups\             (مجلد النسخ الاحتياطية التلقائية اليومية)
```

#### ملف الأسرار المشفر:
```text
%APPDATA%\mg-account\secrets.dat
```
يتم تشفيره تلقائياً بمفتاح عتاد الجهاز عبر تقنية **Electron safeStorage** (Windows DPAPI)، ويحتوي على مفاتيح الأمان في الذاكرة دون حفظها كنصوص صريحة.

#### ملف إعدادات سطح المكتب:
```text
%APPDATA%\mg-account\desktop-config.json
```

### 3. الأسرار التلقائية عند أول تشغيل (Automatic In-Memory Secrets)
عند تشغيل التطبيق لأول مرة على أي جهاز جديد:
1. يقوم التطبيق تلقائياً بتوليد مفاتيح عشوائية فائقة الأمان مشفرة تشمل:
   - `CREDENTIALS_KEY` (مفتاح 64 خانة بنظام Hex لتشفير الجلسات والملفات).
   - `PASSWORD_PURGE_MASTER` (كلمة مرور تفريغ الإنتاج المعقدة).
   - `DEVICE_ACTIVATION_CODE` (كود تفعيل الأجهزة).
   - `SETUP_TOKEN` (توكن تهيئة النظام).
   - `ETA_CLIENT_SECRET` و `ETA_TOKEN_PIN` (مفاتيح منظومة الفاتورة).
2. يتم تشفير هذه المفاتيح وحفظها في `secrets.dat`.
3. تُمرر هذه القيم في الذاكرة الحية فقط (`process.env`) إلى خادم Express دون تخفيف أي من فحوصات الأمان الصارمة الخاصة ببيئة الإنتاج.

### 4. حساب المدير المباشر وتغيير كلمة المرور (Direct Admin Setup)
- إذا تم تشغيل المنظومة لأول مرة وقاعدة البيانات فارغة من المستخدمين، ينشئ التطبيق تلقائياً حساب المدير الرئيسي:
  - **اسم المستخدم / البريد:** `admin@desktop.local` (أو `admin`)
  - **الدور:** `ADMIN`
  - **كلمة المرور المؤقتة:** كلمة مرور عشوائية من 12 خانة مشفرة بـ `bcrypt`.
- **العرض لمرة واحدة:** تظهر شاشة منبثقة أنيقة في الواجهة لمرة واحدة فقط تحتوي على بيانات الدخول مع زر **"نسخ كلمة المرور"**.
- يتم مسح كلمة المرور المؤقتة من ذاكرة التطبيق فور قراءتها ولا يتم طباعتها في أي سجلات نهائياً (`console.log` / `logs`).
- يتم تفعيل علامة `mustChangePassword = true`، بحيث يُلزم النظام المدير بتعيين كلمة مرور شخصية جديدة (لا تقل عن 10 أحرف) فور تسجيل الدخول الأول قبل السماح له بالوصول لباقي أقسام المنظومة.

### 5. أمان الشبكة والوصول من أجهزة المكتب (LAN Access Security)
- **الافتراضي:** التطبيق يستمع حصرياً على العنوان المحلي `127.0.0.1`. لا يمكن لأي جهاز آخر على الشبكة الاتصال به.
- **خيار أجهزة المكتب (للمدير فقط):**
  - من قائمة **"الإعدادات" ⚙️** > **"المظهر واللغة والأمان"**، يظهر خيار خاص بالمدير: **"الوصول عبر شبكة المكتب المحلية (Desktop LAN)"**.
  - عند التفعيل يظهر تحذير أمني واضح مع رابط الوصول المحلي (مثال: `http://192.168.1.50:3000`).
  - عند إعادة تشغيل التطبيق، يستمع الخادم على `0.0.0.0` ليسمح لأجهزة المحاسبين في نفس المكتب بالدخول للمنظومة عبر متصفح الويب.

### 6. النسخ الاحتياطي اليدوي والاستعادة المخصصة
تم توفير زرين مخصصين في تبويب **النسخ الاحتياطي** بالمنظومة:
1. **💾 حفظ نسخة في مجلد تختاره (Choose Backup Folder):**
   - يفتح نافذة النظام لاختيار مكان حفظ ملف النسخة الاحتياطية (مثل فلاشة USB أو قرص خارجي).
   - يقوم بتحميل وحفظ أرشيف ZIP شامل لقاعدة البيانات وكافة المستندات المرفوعة.
2. **📥 استعادة نسخة من ملف (Restore from File):**
   - يتيح اختيار ملف `.zip` أو `.db` خارجي.
   - يقوم بحذف ملفات القفل المؤقتة (`-wal` و `-shm`) واستبدال البيانات بدقة وإعادة تشغيل التطبيق تلقائياً.

### 7. كيفية البناء والتطوير محلياً (Build & Development)

#### متطلبات بيئة التطوير:
- **Node.js** إصدار 20 أو 22 LTS.
- **Windows Build Tools** (مطلوبة لتجميع better-sqlite3):
  ```bash
  npm install --global --production windows-build-tools
  ```
  أو تثبيت **Visual Studio Community** مع حزمة **Desktop development with C++**.

#### أوامر التشغيل والبناء:
```bash
# 1. تثبيت الحزم والمكتبات
npm install

# 2. تشغيل نسخة سطح المكتب في بيئة التطوير
npm run desktop:dev

# 3. بناء ملف التثبيت لويندوز Setup.exe (NSIS Installer)
npm run desktop:build

# 4. إعادة بناء مكتبة better-sqlite3 عند ترقية نسخة Electron
npm run desktop:rebuild
```

- يتم إخراج ملف التثبيت النهائي في المجلد:
  ```text
  release/MG Account Setup 1.2.0.exe
  ```

### 8. البناء التلقائي عبر GitHub Actions
الملف `.github/workflows/build-desktop.yml` مبرمج لتنفيذ عملية البناء آلياً على بيئة سحابية:
- **نظام Windows:** يبني `MG Account Setup.exe` بنظام NSIS لمعمارية `x64` ويرفعه كأصل جاهز للتحميل.
- **نظام macOS:** يبني حزمة `MG-Account.dmg` لمعماريتي `arm64` و `x64` (Universal) بدون حاجة لشهادة توقيع مدفوعة (`identity: null`).

### 9. نظام الترخيص ووضع التشغيل (License Modes & Features)
تدعم المنظومة نظام ترخيص موقع رقمياً (Ed25519) مع إمكانية تحديد وضع التشغيل والخصائص المتاحة:
1. **وضع التشغيل (`mode`):**
   - `"ONLINE"`: يتيح التشغيل المتصل مع تفعيل كافة الميزات السحابية والذكاء الاصطناعي وواتساب والربط الضريبي افتراضياً.
   - `"OFFLINE"`: وضع أوفلاين آمن، حيث تُعطل تلقائياً خدمات Gemini AI و WhatsApp و Firebase Sync وإرسال الفواتير لمصلحة الضرائب (ETA Submit)، بينما يظل إدخال وتجهيز بيانات الفواتير والعملاء متاحاً بالكامل محلياً.
   - **التوافق العكسي:** الأكواد القديمة التي لا تحتوي على حقل `mode` تُعامل تلقائياً كـ `OFFLINE`.
2. **الخصائص التفصيلية (`features`):**
   - `cloudSync`: مزامنة السحابة (Firebase Sync).
   - `ai`: مساعد الذكاء الاصطناعي (Gemini AI & OCR).
   - `whatsapp`: محرك واتساب للأعمال (WhatsApp Business API).
   - `eta`: الإرسال المباشر لمنظومة الفاتورة الإلكترونية.
3. **أداة إصدار التراخيص (`tools/generate-license.mjs`):**
   - يدعم المعاملات `--mode=ONLINE` أو `OFFLINE` وخصائص الباقة (`--cloudSync=true/false`, `--ai=true/false`, `--whatsapp=true/false`, `--eta=true/false`).
   - مثال:
     ```bash
     node tools/generate-license.mjs --issue --office="مكتب المحاسبة" --plan=ONLINE --mode=ONLINE --cloudSync=true --ai=true --whatsapp=true --eta=true --days=365 --maxUsers=15
     ```
4. **التفعيل الديناميكي:**
   - يمكن لصق كود الترخيص الجديد عبر شاشة التفعيل (بصلاحية `ADMIN` فقط) دون الحاجة لإعادة تشغيل الخادم ودون أي فقد للبيانات، مع تسجيل العملية في سجل المراجعة (Audit Trail).
