# دليل استخدام منظومة MG-Account المحاسبية والضريبية الشاملة (الإصدار v1.2.0)
**دليل تشغيلي متكامل لمكاتب المحاسبة القانونية والمراجعة والشركات وفق المعايير المصرية (EAS) والدولية (IFRS)**

---

## 1. نظرة عامة على المنظومة (Overview)

### ما هو برنامج MG-Account؟
منظومة **MG-Account** هي تطبيق محاسبي وإداري وضريبي شامل موجه لمكاتب المحاسبة القانونية ومراقبي الحسابات والشركات في جمهورية مصر العربية والشرق الأوسط. يُتيح البرنامج إدارة الدورة المحاسبية الكاملة من تكويد شجرة الحسابات وتسجيل قيود اليومية، وصولاً إلى استخراج الميزانيات والقوائم المالية الرسمية والإيضاحات المتممة، وتقرير مراقب الحسابات، وإقرارات مصلحة الضرائب المصرية (ETA)، ومطابقة الفواتير والإيصالات الإلكترونية، ودراسات التسهيلات والائتمان البنكي.

---

### التقنيات البرمجية المستخدمة بالمنظومة
تعتمد المنظومة على بنية هندسية عالية التأمين والأداء (مصدر الكود: `package.json` و `server.ts`):
1. **الواجهة الأمامية (Frontend):** React 19 مع TypeScript و Tailwind CSS v4 ومحرك Vite 6 للتحميل الفوري.
2. **الخادم الخلفي (Backend Server):** خادم Express 4 مبني بلغة TypeScript عبر ملف `server.ts`.
3. **قواعد البيانات (Databases):**
   - **قاعدة البيانات المحلية المباشرة:** SQLite عبر حزمة `better-sqlite3` فائقة السرعة مع المعاملات الذرية (`data/app.db`).
   - **السحابة الاختيارية:** Firebase Firestore و Firebase Auth للتزامن والعمل الميداني المزدوج.
4. **الذكاء الاصطناعي:** حزمة `@google/genai` الرسمية من Google لاستقراء الفواتير الممسوحة والتحليل الضريبي الذكي.
5. **الأمان والتأمين:** مكتبة Helmet لتطبيق سياسات الأمان المغلقة (CSP)، وتشفير بوابات العملاء، وفحص السلامة الهيكلية للملفات المرفوعة (Magic Bytes Verification - `server.ts` السطر 5-23).

### مقارنة وضع السيرفر المحلي (SQLite) ووضع الخدمة السحابية (Firebase)

| وجه المقارنة | وضع السيرفر المحلي (Local SQLite Mode) | وضع الخدمة السحابية (Firebase Cloud Mode) |
|---|---|---|
| **محرك التشغيل** | خادم Express (`server.ts`) مع قاعدة بيانات SQLite محلياً في `data/app.db`. | تسجيل دخول عبر Firebase Auth وتزامن سحابي في Firestore عبر `cloudSync.ts`. |
| **تخزين الوثائق والأرشيف** | أرشفة الملفات محلياً في مجلد `data/documents/<clientId>/<year>` عبر Multer. | تخزين البيانات والوثائق سحابياً عبر خدمات Firestore Storage. |
| **الأمان وإدارة الجلسات** | حماية محلياً برقم IP والبريد الإلكتروني بجدول `login_attempts` برمز جلسة SQLite. | حماية عبر متطلبات `firestore.rules` وتسجيل الدخول بحسابات Google Auth / Firebase. |
| **متى يُستخدم هذا الوضع؟** | **الوضع الافتراضي والأوصى به لمكاتب المحاسبة:** لسرعته الفائقة وعدم اعتماده على إنترنت. | عند الحاجة لتعدد الفروع والعمل الميداني المباشر من أجهزة مختلفة. |

## 2. التشغيل والإعداد (Setup & Environment Variables)

### خطوات التشغيل من الصفر

#### أ) بيئة التطوير (Development Setup):
1. تثبيت الحزم والمكتبات:
   ```bash
   npm install
   ```
2. ضبط متغيرات البيئة بإنشاء ملف `.env` بناءً على `.env.example`.
3. تشغيل سيرفر التطوير المتكامل:
   ```bash
   npm run dev
   ```
   *تشغيل `server.ts` عبر `tsx` وربط Vite Middlewares على المنفذ `3000` (`server.ts` السطر 67).*

#### ب) بيئة الإنتاج (Production Deployment):
1. بناء المشروع وتحزيم الواجهة والخادم:
   ```bash
   npm run build
   ```
   *ينتج مجلد `dist/` يحتوي على الواجهة المجمعة وملف `dist/server.cjs` المخصص للتنفيذ (`package.json` السطر 8).*
2. التأكد من تحديد قيمة `SETUP_TOKEN` إذا كانت قاعدة البيانات خالية.
3. تشغيل الخادم الرسمي:
   ```bash
   npm start
   ```
   *ينفذ `node server.ts` أو `dist/server.cjs` على البورت المكتوب في المتغير `PORT` (أو 3000).*

## 3. إنشاء الحساب وتفعيله والصلاحيات (Account & RBAC)

### أ) إنشاء أول مدير في النظام (`setup-admin`)
عند تشغيل المنظومة لأول مرة على السيرفر المحلي:
1. يوجه المستخدم إلى شاشة الإعداد الأولية أو يستدعي المسار المباشر `/api/auth/setup-admin` (`server.ts` السطر 630).
2. **الشروط اللازمة:**
   - أن تكون قاعدة بيانات المستخدمين خالية تماماً (0 مستخدمين) **أو** تقديم رمز `setupToken` المطابق لـ `SETUP_TOKEN` (`server.ts` السطر 632-637).
   - أدخل اسم المدير، البريد الإلكتروني، وكلمة مرور **لا تقل عن 10 أحرف** صراحةً (`server.ts` السطر 640: `password.length < 10`).
3. **النتيجة والزر المستخدم:**
   - يضغط المستخدم زر **"إنشاء حساب المدير الرئيسي"**.
   - يتم إنشاء الحساب بتشغيل دور **`ADMIN`** وتفعيل كافة الصلاحيات الفردية الـ 8 فوراً.
   - تنشأ جلسة دخول تمتد لمدة **7 أيام** (`server.ts` السطر 671: `7 * 24 * 60 * 60 * 1000` ms).
4. **عند وجود مستخدمين سابقين:**
   - يُرفض الطلب فوراً باستجابة 400 ورسالة صريحة: *"تم إعداد حساب المدير مسبقاً ولا يمكن إنشاء مدير عبر هذا الرابط."* (`server.ts` السطر 650).

---

### ب) تسجيل الدخول وآليات التأمين المتقدمة للعمل المحاذي (Server-First & PBKDF2 Offline Auth)

1. **إلغاء بيانات الدخول الافتراضية:** تم إلغاء حساب `admin/admin` الافتراضي نهائياً لحماية النظام من الاقتحام. يتم إنشاء أول مدير رسمياً عبر شاشة `setup-admin`.
2. **تدفق تسجيل الدخول المباشر (Server-First Authentication):**
   - عند إدخال البريد الإلكتروني وكلمة المرور، يتم إرسال الطلب أولاً لخادم السيرفر المباشر (`POST /api/auth/login`).
   - عند نجاح المصادقة، يرجع السيرفر دور المستخدم وصلاحياته الفردية الدقيقة المعتمدة بجدول `users`.
   - يتم توليد هاش مشفر مملّح بخوارزمية **PBKDF2** (بعمق 100,000 دورة تشفير مع Salt عشوائي فريد لكل جلسة عبر Web Crypto API) وتخزينه محلياً مع ملف المستخدم وصلاحياته المعتمدة لمدة **7 أيام فقط**.
   - **منع تخزين السر:** يُحظر تماماً تخزين أي كلمة مرور أو PIN بنص عادي (Plaintext) في `localStorage`.
3. **الدعم المحمي للعمل أوفلاين (Secure Offline Mode):**
   - عند انقطاع الإنترنت أو عدم القدرة على الوصول للسيرفر، يتم التحقق أوفلاين عبر الهاش المشفر المنسوخ من آخر دخول أونلاين ناجح.
   - يُسمح بالدخول أوفلاين **لنفس الحساب المسبق فقط** بالصلاحيات المحفوظة ذاتها لمدة أقصاها **7 أيام**.
   - تظهر شارة صريحة بالواجهة: **"وضع أوفلاين (غير متصل بالسيرفر)"**.
   - **حد المحاولات أوفلاين:** أقصى حد 5 محاولات فاشلة خلال 15 دقيقة، ويتم قفل المحاولات المحلية تلقائياً عند تجاوز الحد.
4. **شاشة قفل الجلسة (PIN Lock):**
   - تظل شاشة القفل السريع (PIN/Pass) مخصصة فقط لفك قفل الجلسة النشطة الحالية بعد تسجيل دخول ناجح دون منح أي صلاحيات جديدة.
5. **توحيد الحد الأدنى لكلمة المرور:**
   - تم توحيد الحد الأدنى لكلمة المرور في كافة الشاشات (التسجيل، إعداد المدير، وتغيير Pass) ليكون **10 أحرف/أرقام صراحةً**.

---

### ج) إنشاء مستخدم جديد وتفعيل حسابات الانتظار (`PENDING`)

1. **طريقة الإنشاء:** يفتح المدير (`ADMIN`) نافذة **"إدارة المستخدمين والصلاحيات"** (`UserManagementModal.tsx`) ويضغط زر **"إضافة مستخدم جديد"**.
2. **حالة الانتظار (`PENDING`):** عند تسجيل أي بريد جديد محلياً أو سحابياً، تبدأ حسابه تلقائياً بدور `PENDING` مع إيقاف كافة الصلاحيات الفردية الـ 8 (`server.ts` السطر 546)، وتُحظر جميع مسارات النظام عنه باستثناء فحص الجلسة وتسجيل الخروج (`/api/auth/me` و `/api/auth/logout`).
3. **خطوات المدير لتفعيل الحساب بالأزرار الواجهية:**
   - يفتح المدير نافذة **"إدارة المستخدمين والصلاحيات"**.
   - يحدد المستخدم المطلوب من قائمة الحسابات.
   - يضغط زر **"تعديل الحساب والصلاحيات"** (أيقونة القلم).
   - يفتح القائمة المنسدلة **"الدور الوظيفي"** ويختار أحد الأدوار: `ADMIN` / `AUDITOR` / `ACCOUNTANT` / `SECRETARY`.
   - يفعّل مفاتيح الصلاحيات الفردية الـ 8 حسب حاجة العمل.
   - يضغط زر **"حفظ التغييرات"** لتفعيل الحساب فوراً.

### و) وضع Firebase وتجهيز الحسابات (عند التفعيل)
- يتم تسجّيل الدخول بحساب Google أو البريد الإلكتروني في بوابة Firebase (`FirebaseAuthGate.tsx`).
- يُنشأ سند المستخدم تلقائياً في مجموعة `users/{userId}` بشرط أن يبدأ بـ `role = 'PENDING'` مع تعطيل كافة الصلاحيات الفردية الـ 8.
- تمنع قواعد `firestore.rules` للمستخدم العادي تغيير دوره بنفسه أو القراءة والكتابة خارج الحدود المصرح بها.
- يقوم المدير المعين بتغيير دور الحساب من `PENDING` إلى الدور المطلوب وتفعيل الصلاحيات من لوحة الإدارة.

### ز) المشاكل الشائعة وحلولها السريعة
1. **نسيت كلمة المرور:** يطلب المستخدم من المدير إعادة تعيين كلمة المرور من نافذة "إدارة المستخدمين" عبر زر **"تغيير كلمة المرور السريعة"**، أو استخدام كلمة المرور الماستر.
2. **الحساب مقفول (Locked):** الانتظار لمدة 15 دقيقة (أو ساعة) حتى ينتهي الحظر الزمني التلقائي المعتمد بالسيرفر.
3. **الحساب معلق (`PENDING`):** تواصل مع مدير المكتب لتعديل دورك الوظيفي وتفعيل الشاشات والصلاحيات المسموح لك بها.

## 4. شرح الشاشات والمراكز بالتفصيل (Hubs & Screens)

### 1) الرئيسية (Dashboard)
- **اسمها بالقائمة:** "الرئيسية"
- **الغرض منها:** عرض ملخص مؤشرات المكتب المحاسبي، الأرباح، القيود غير المرحّلة، مواعيد الإقرارات الضريبية المستحقة، واختصارات سريعة.
- **من يصل إليها:** كافة المستخدمين المعتمدين (`ADMIN`, `ACCOUNTANT`, `AUDITOR`, `SECRETARY`).
- **خطوات الاستخدام:** التصفح المباشر للرسوم البيانية ومتابعة التنبيهات وإضافة التذكيرات.
- **المخرجات:** طباعة ملخص مؤشرات النشاط وسجل المهام.

### 2) اليومية والقيود (Journal & Ledger)
- **اسمها بالقائمة:** "الدفتر" ← "القيود واليومية"
- **الغرض منها:** إدخال وتعديل قيود اليومية، القيود الافتتاحية، قيود التسوية، وقيود الإقفال، ومتابعة الأرصدة بالجنيه المصري والعملات الأجنبية.

## 5. دورة العمل المحاسبية الكاملة (كامل الخطوات العملية)

مثال عملي تطبيقي لبدء العمل على شركة جديدة من الصفر حتى استخراج الميزانية والقوائم المالية:

1. **الخطوة 1: إنشاء ملف العميل:**
   - توجه للشاشة رقم `2` **"العملاء"** ← اضغط **"إضافة عميل جديد"**.
   - أدخل اسم الشركة: *"شركة المصرية للتجارة والتوريدات"* - الشكل القانوني: *"شركة ذات مسؤولية محدودة"* - السجل التجاري والبطاقة الضريبية.
2. **الخطوة 2: مراجعة دليل الحسابات:**
   - توجه للشاشة رقم `3` **"الدفتر"** ← اختر تبويب **"دليل الحسابات"**.
   - تأكد من وجود وتكويد الحسابات الفرعية المطلوبة: حساب البنك (`1112`)، المبيعات (`4110`)، وضريبة القيمة المضافة (`2130`).
3. **الخطوة 3: إدخال قيد اليومية:**
   - في شاشة **"القيود واليومية"** ← اضغط زر **"قيد جديد"**.
   - اختر العميل والبيان: *"إثبات تحصيل قيمة خدمات وتوريدات"*.
   - السطر 1: مدين - البنك الأهلي (`1112`) - المبلغ: `114,000 ج.م`.
   - السطر 2: دائن - إيرادات المبيعات (`4110`) - المبلغ: `100,000 ج.م`.
   - السطر 3: دائن - ضريبة القيمة المضافة 14% (`2130`) - المبلغ: `14,000 ج.م`.
   - تأكد من توازن القيد (الفارق `0.00 ج.م`) ← اضغط **"حفظ القيد"**.
4. **الخطوة 4: إصدار الفاتورة الضريبية:**
   - توجه لـ **"الفواتير والمبيعات"** ← اضغط **"فاتورة جديدة"** وأصدر الفاتورة المعتمدة بـ QR Code.
5. **الخطوة 5: ترحيل القيد:**
   - اضغط زر **"ترحيل القيد"** لتتحول حالة القيد إلى مرحّل (`isPosted = true`) وتعتمد مبالغه بالنظام.
6. **الخطوة 6: مراجعة ميزان المراجعة:**
   - افتح تبويب **"ميزان المراجعة"** لمطابقة مجاميع وأرصدة الحركة قبل وبعد الترحيل.
7. **الخطوة 7: استخراج القوائم المالية:**
   - توجه لمركز **"القوائم المالية المعتمدة"** ← اضغط **"تحديث ومطابقة الأرصدة"**.
   - يتم توليد قائمة المركز المالي وقائمة الدخل والإيضاحات المتممة تلقائياً.
8. **الخطوة 8: إقفال الفترة المالية:**
   - توجه لـ **"القفل الزمني للفترات"** (للمدير) واقفل الفترة المالية المكتملة لمنع أي تعديل خلفي.
9. **الخطوة 9: الطباعة والتصدير:**
   - اصدر المجلد المالي كاملاً كـ PDF معتمد أو Excel.

## 6. النسخ الاحتياطي والاستعادة (Backup & Restore)

### أ) النسخ الاحتياطي التلقائي (Automatic Daily Backup)
- ينفذ خادم السيرفر محلياً يومياً عند الساعة 23:00 تلقائياً عملية نسخ لقاعدة البيانات في المجلد (`server.ts` السطر 403-413):
  `data/backups/backup_YYYY-MM-DD_HH-MM-SS/app.db`
- يحتفظ النظام بأحدث **30 نسخة احتياطية** ويقوم بتنظيف القديم أوتوماتيكياً (`server.ts` السطر 391).

### ب) النسخ الاحتياطي اليدوي (Manual Export)
- يفتح المدير نافذة **"النسخ الاحتياطي والاستعادة"** من أعلى الشاشة.
- يضغط على **"تحميل نسخة احتياطية (Download Backup)"** لاستخراج ملف DB / JSON موثق رقمياً بـ HMAC.

### ج) خطوات الاستعادة وفحص السلامة (Restore Process - المصدر: `server.ts` السطر 78)
1. يتطلب تنفيذ الاستعادة عبر المسار `/api/server-backups/restore` (بحجم أقصى **50MB**) أن يكون المستخدم بدور **`ADMIN`**.
2. يرفع المدير ملف النسخة الاحتياطية.
3. **فحص السلامة الآلي (SQLite Integrity Check):**
   - يقوم السيرفر بفتح الملف مؤقتاً وتشغيل أمر `PRAGMA integrity_check`.
   - إذا لم ترجع النتيجة `ok` (وجود تلف)، يتم إلغاء العملية فوراً واسترجاع كود 400 ورسالة: *"فشل فحص سلامة النسخة الاحتياطية (Integrity Check Failed). قد تكون البيانات تالفة."*
4. **جملة التأكيد والنقل:**
   - يشترط كتابة جملة التأكيد المطلوب بالنافذة قبل البدء.
5. **النسخة الطارئة والتنفيذ:**
   - يقوم السيرفر بإنشاء نسخة احتياطية طارئة للحالة الحالية قبل الاستبدال، ثم يستبدل قاعدة `app.db` ويعيد تشغيل الخادم تلقائياً.

## 7. الأمان وأفضل الممارسات (Security & Best Practices)

1. **كلمات المرور والتأمين:**
   - الالتزام بكلمة مرور **لا تقل عن 10 أحرف** صراحةً (`server.ts` السطر 640).
   - حماية رمز الإعداد `SETUP_TOKEN` وعدم مشاركته في البيئات العامة.
2. **تشفير بوابات العملاء:**
   - يتم تشفير كلمات مرور بوابات الضرائب والعملاء المنسوخة في قواعد البيانات عبر خوارزمية تشفير معتمدة بمفتاح `CREDENTIALS_KEY`.
3. **عدم التلاعب بسجل الرقابة (`auditLogs`):**
   - الكود يمنع تماماً أي عمليات حذف أو تعديل في جدول `auditLogs` لجميع المستخدمين والمدراء لضمان التتبع القانوني المعتمد.
4. **قواعد حظر المخاطر:**
   - عدم إيقاف بروتوكول HTTPS في بيئة الإنتاج.
   - عدم إعطاء صلاحيات `canManageUsers` أو `canDeleteRecords` إلا للشركاء والمدراء المسؤولين.

## 8. الأعطال الشائعة والأسئلة المتكررة (Troubleshooting & FAQ)

1. **س: يظهر لي خطأ (413 Payload Too Large) عند الحفظ؟**
   - **السبب:** البيانات أو الملف المرفوع أكبر من الحد المسموح به للمسار.
   - **الحل:** تم رفع الحد في مسار الترحيل الشامل (`/api/data/migrate-all`) والنسخ الاحتياطي و OCR لـ **50MB** (`server.ts` السطر 81)، و **10MB** لمسارات الكيانات العامة والذكاء الاصطناعي وجماعي الضرائب (`server.ts` السطر 96).
2. **س: تم قفل حسابي برسالة (تم قفل الحساب مؤقتاً)؟**
   - **السبب:** إدخال كلمة المرور بشكل خاطئ لأكثر من 5 محاولات متتالية أو 20 محاولة على البريد الإلكتروني.
   - **الحل:** انتظر 15 دقيقة (أو ساعة) وسيفك القفل الزمني التلقائي، أو اطلب من المدير إعادة تغيير كلمة المرور من لوحة المستخدمين.
3. **س: تظهر رسالة "الميزة معطلة" عند تشغيل فحص الذكاء الاصطناعي؟**
   - **السبب:** عدم تفعيل خيار موافقة إرسال البيانات للجيمناي في بروفايل المكتب (`/api/settings/gemini-consent`) أو غياب مفتاح `GEMINI_API_KEY`.
   - **الحل:** ادخل لإعدادات بروفايل المكتب وفعّل موافقة الذكاء الاصطناعي وادخل المفتاح في متغيرات البيئة.
4. **س: كيف أعرف أن القيد المحاسبي مرحّل ومغلق؟**
   - **العلامة:** القيد المرحّل تظهر عليه علامة مراجعة معتمدة وتكون خاصية `isPosted = true` ولا يمكن تعديله إلا لمن يمتلك صلاحية `canEditPostedEntries`.

## 9. قائمة النقاط غير المؤكدة والملفات المعتمد عليها

### أ) الملفات المعتمد عليها في إعداد هذا الدليل (Files Relied Upon):
- `server.ts` - السيرفر الخلفي واشترطات الأمان والجسور والتحقق من الأحجام والأقفال الزمانية (الحد الأدنى لكلمة المرور 10 أحرف، مدة الجلسة 7 أيام).

- `src/App.tsx` - مسارات التنقل والنوافذ المنبثقة والتحكم بالوضع المحلي والسحابي.
- `src/types.ts` - جميع التعريفات والأنواع الهيكلية والصلاحيات وسجل الرقابة.
- `src/server/access.ts` - مصفوفة التحكم في الوصول والأدوار والصلاحيات الفردية الـ 8.
- `firestore.rules` - قواعد الأمان والوصول السحابي بقواعد بيانات القراءة والكتابة.
- `src/services/securityAuth.ts` - آليات التشفير وحظر الهجمات وتوقيت الردود.

- `src/components/UserManagementModal.tsx` - نافذة التحكم بالمستخدمين وتفعيل حسابات الانتظار PENDING.
- `src/components/hubs/*` - جميع شاشات ومراكز التطبيق العملي.
